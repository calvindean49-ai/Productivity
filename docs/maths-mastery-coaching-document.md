## §1 The goal

**Develop the attributes of a mathematician as fully as possible.** Not breadth across every branch of
mathematics — unreachable, and not the point — but the qualities themselves. Exams are measuring
instruments and forcing deadlines; the plan narrows to each one only as its date approaches.

The attributes:

| Attribute | Observable evidence |
|---|---|
| Fluency | Accurate, efficient standard technique without prompting |
| Conceptual understanding | Explains why a result works, its assumptions, where it fails |
| Method selection | Distinguishes competing methods and checks conditions first |
| Proof and rigour | Complete arguments, definitions stated, no hidden assumptions |
| Unfamiliar problem solving | Productive progress without a rehearsed template |
| Connections and representation | Moves between algebraic, geometric, graphical, verbal forms; links topics |
| Generalisation and invention | Weakens hypotheses, builds examples/counterexamples, extends results |
| Communication | Explains so another person can verify every step |
| Timed precision | Keeps method choice and accuracy under real constraints |
| Metacognition | Predicts uncertainty, finds the real obstruction, changes strategy deliberately |
| **Beliefs and control** | **Persists past the point where the problem stops resembling anything rehearsed; treats "I don't see it yet" as normal rather than as evidence of limit** |

*(Beliefs added 22 Sept on the Research Review's finding: Schoenfeld's framework has four components —
resources, heuristics, control, beliefs — and his data showed students abandoning correct approaches
because they believed a problem should be solvable in five minutes. Measured by time-to-first-abandonment
on unfamiliar problems.)*

**Model of expertise.** Declarative knowledge (what is true and why — the schema), procedural knowledge
(how to execute) and conditional knowledge (when and why to use which method) develop *together*, not in
sequence — procedural practice builds schema as much as it depends on it. Conditional knowledge is where
experts most separate from strong students; most of Calvin's logged failures are conditional. "Thinking
outside the box" is not a fourth kind of knowledge: it is transfer, and it appears when the schema is
richly connected and has been exercised on unfamiliar problems.

**Efficiency is the unlock, not the point.** Time recovered goes to other subjects, sport and leisure, not
to more maths hours.

**Tension to manage:** TMUA trains fast pattern-matching and never looking back. Where exam optimisation
and mathematical development conflict, name the conflict rather than quietly choosing the exam.

## §4 Evidence rules

**Nothing is solid on self-report or because it felt clear in a session with Claude.**

| State | Evidence required |
|---|---|
| Unmeasured | No recent cold evidence |
| Building | Success only with instruction, scaffolding or immediate repetition |
| Reliable | Two cold successes at **10–14 days**, then **4–6 weeks**, including correct condition and method selection |
| Transferable | Reliable plus an unfamiliar transfer problem, an explanation and a meaningful connection |

*(Intervals revised 22 Sept. Cepeda et al.: the optimal study gap is 10–20% of the retention interval.
TMUA is ~15 weeks out, A-levels ~36. A 2-day retest mostly measures recency and produces false
"Reliable" ratings.)*

Only unassisted work counts as cold evidence. Retest dates go straight onto the Google Calendar called
"Calendar".

**Assistance scale** — record on every attempt: 0 none (cold) · 1 metacognitive prompt · 2 small
conceptual hint · 3 method or intermediate claim supplied · 4 worked step or solution shown.

**Error types:** knowledge · condition/method selection · recognition (known, noticed too late) ·
logic/proof · algebra/calculation · interpretation (misread condition or command) · route choice ·
timing/confidence. Do not disguise a condition failure as a careless reading error.

**Sources:** mark against official solutions first (OCR, UKMT/BMOS, UAT-UK). Claude's custom diagnostics
are good for *finding* gaps but do not by themselves prove a topic solid — confirm with official
past-paper questions.

## §5 How each attribute gets measured

No single test gives the full profile. Layer 0 reads three or four attributes well; the whole battery
covers ten of eleven.

| Attribute | Instrument |
|---|---|
| Fluency, method selection | Layer 0 diagnostic (Q11 specifically for selection) |
| Conceptual understanding | Boundary-case probe: state the hypothesis that makes a method valid, then construct a case where dropping it breaks the result |
| Timed precision | Full TMUA paper |
| Proof and rigour, unfamiliar problem solving | Graduated proof set (hard SMC, Senior Kangaroo, accessible BMO1) — replaces a full BMO1 paper to avoid a floor effect |
| Connections | Schema reconstruction (unprompted concept map) |
| Communication | No-notes explanation |
| Metacognition | Prediction-vs-result gap on every marked part |
| **Beliefs and control** | **Time-to-first-abandonment on an unfamiliar problem. One number per session.** |
| Generalisation, taste | Only visible over weeks: look-backs, conjecture book, struggle-floor logs |

**Limits of the baseline:** it samples rather than surveys; one bad evening looks like a gap; olympiad
content knowledge (NT, combinatorics, geometry, inequalities) is almost entirely unmeasured by it; a
schema map shows what is recalled unprompted, not everything known. It is a first version of the profile,
filled in by everything after it.

## §8 Tracking

Lightweight by design — no full attribute × level × topic grid until real data exists to fill it
(building it first is the planning-instead-of-maths pattern).

**Log row — eight fields, one line:**

```
date | source | topic | attribute | cold?(0-4) | outcome | error type + the exact failed step | next retest
```

**The only field that must never be blank is `next retest`** — it is the only one that causes anything to
happen. If two consecutive weeks pass with no entries, the log is not restarted: it is cut to that one
field and nothing else. A one-field log that runs beats an eight-field log that doesn't.

The attribute profile is *derived* by filtering the log: attributes with no rows are the gaps.
**Monthly attribute review:** which attributes have thin evidence → aim next month's problem choice there.

Weekly metrics: **which tier was actually hit** · problems solved *and written to marking standard* ·
slip count, driven to zero · conjecture-book entries (empty three weeks running = the programme has become
exam prep).

## §9 Mathematician-quality protocols

- **Look-back (10 min after every solved problem):** second or shorter proof? weakest hypothesis it
  survives? does it generalise? what was the real obstruction? — **and make these topic-specific, not
  generic.** Pólya-level heuristics are the wrong grain size and do not transfer. In geometry the standard
  weakenings are: drop the cyclic condition, drop convexity, replace an equality with an inequality, move a
  point to a limiting position. In number theory: weaken the modulus, replace a prime with a prime power,
  let the exponent vary.
- **Struggle floor (Saturday):** 45 minutes before any hint; log where the argument broke — **then the
  canonical solution in full**, contrasted step by step against the attempt, identifying which step of the
  model solution corresponds to the point where the attempt failed. Withholding it converts productive
  failure into failure.
- **Conjecture book:** questions noticed while working, no obligation to solve.
- **No-notes explanation (10 min/week):** kept because it exposes false understanding, not for admissions.
- **Woven in:** every write-up is a proof; "clearly" is a flag to justify; state definitions before
  reasoning; re-derive every final numeric step by a second route.

## §10 How Claude coaches

- **Mode is chosen by evidence state, not applied uniformly:**

| Evidence state | Mode |
|---|---|
| **Unmeasured / never opened** | Worked example in full, then faded practice: complete solution → last step removed → last two removed → full problem. Self-explanation prompt at each stage. |
| **Building** | Socratic, with the hint ladder. Two failures on the same missing prerequisite → teach it directly. |
| **Reliable** | Cold problems, no hints, unfamiliar framings. |
| **Transferable** | Generalisation and invention: weaken hypotheses, build counterexamples, extend. |

- **One problem at a time;** complete attempt before evaluation. **Hint ladder:** clarify the task → point
  to a definition → suggest a representation → offer an intermediate claim → only then a worked step.
- **At least 70% of a session is Calvin's independent work.** Timed blocks are never interrupted; debrief
  after.
- **After a problem:** critique every unsupported step against the verified solution; classify the error;
  require a corrected solution in Calvin's own words; one connection, one boundary case, one
  generalisation; schedule the retest.
- **Interleave:** within any set, no two consecutive problems use the same method, and never state which
  method to use.
- **Stop planning once the next task is clear.** Resource-compiling, tooling talk, tracker design and the
  OS project are the documented displacement pattern — name it and redirect.
- **Hard stops** when sleep or diminishing returns win. **Deadline protection:** flag unprompted if maths
  eats the personal statement or A-level content.
- **Honesty:** rate ideas out of 10; say "you're wrong" and why; state uncertainty instead of guessing.
- **Known limits:** project files are read-only to Claude, so STATUS updates are handed to Calvin to swap
  in. Claude cannot start sessions — weekly reviews happen only when Calvin opens one. Claude *can* write
  retest dates and blocks onto Google Calendar.

**Session shape:** read STATUS → work → look-back → log errors by type and attribute → output a
replacement STATUS.
